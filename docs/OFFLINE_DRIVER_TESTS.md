# Проверка водительского PWA без сети

Документ для тестировщика. Проверять с телефона (установленное PWA) или в Chrome DevTools: `Network → Offline` / режим полёта. Роль везде — **водитель**, если не указано иное.

Перед серией: войти в сеть, открыть назначенные рейсы, активный рейс, чат рейса, чаты, зарплату и уведомления хотя бы раз — чтобы на телефоне были сохранённые данные.

Индикатор связи в шапке: «Нет сети» / «Синхр.» / «Онлайн». Очередь: события, фото, принятия, прочее.

---

## A. Старт и оболочка приложения

### A1. Холодный старт без сети
1. В сети открыть приложение, убедиться что рейс виден.
2. Полностью закрыть PWA.
3. Включить авиарежим.
4. Открыть PWA с иконки.
5. Ожидание: вход сохранён, домашний экран открывается, активный рейс и список рейсов на месте.
6. Негатив: если телефон никогда не открывал рейс онлайн — сообщение, что сохранённых данных нет.

### A2. Сеть пропала на открытом экране
1. Стоять на «Мой рейс» онлайн.
2. Выключить сеть.
3. Ожидание: бейдж «Нет сети», рейс не пропадает, кнопки статусов работают.
4. Негатив: потянуть «обновить» — список не очищается, остаётся кэш.

### A3. Сеть появилась на открытом экране
1. Из A2 включить сеть.
2. Ожидание: «Онлайн» или «Синхр.», очередь уходит, статусы/чаты совпадают с диспетчерской.

### A4. Убить приложение с непустой очередью
1. Офлайн принять рейс / сменить статус / написать в чат.
2. Смахнуть приложение из памяти.
3. Включить сеть, открыть снова.
4. Ожидание: очередь не потерялась, после синхронизации данные на сервере.

### A5. Смена пользователя
1. Выйти и войти другим водителем (нужна сеть).
2. Ожидание: очередь и рейсы прошлого водителя не видны.

---

## B. Принятие рейса

### B1. Принять полностью офлайн
1. В сети открыть назначенный рейс `new` (чтобы он сохранился).
2. Авиарежим → «Принять».
3. Ожидание: статус «в работе», рейс активный, в очереди «принятий 1», сообщение что уйдёт при сети.
4. Включить сеть.
5. Ожидание: у диспетчера рейс принят, очередь пустая.

### B2. Сеть пропала в момент «Принять»
1. Нажать «Принять» и сразу авиарежим (или DevTools Offline на запросе).
2. Ожидание: на телефоне рейс уже принят, не откатывается к `new`, остаётся в очереди.
3. Включить сеть — принятие доходит один раз, без дубля ошибки «already».

### B3. Сеть появилась сразу после принятия
1. Как B1, включить сеть через 1–2 секунды.
2. Ожидание: синхронизация без ручного обновления.

### B4. Принять офлайн рейс, который на сервере уже не новый
1. Диспетчер назначил / водитель принял с другого устройства.
2. На этом телефоне офлайн нажать «Принять» по старому кэшу.
3. Включить сеть.
4. Ожидание: конфликт не ломает экран; рейс в работе; нет бесконечной ошибки в очереди.

### B5. Принять без сохранённого рейса
1. Новый телефон / очистить сайт, авиарежим, открыть рейс из уведомления если получится.
2. Ожидание: «нет сохранённых данных», принятие недоступно.

## C. Смена статуса точки

Покрыть цепочку: выехал (`process`, с ETA) → регистрация → ворота → документы.

### C1. Статус полностью офлайн
1. Активный рейс, авиарежим.
2. «Следующий статус» → подтвердить время (для выезда — заполнить ETA).
3. Ожидание: карточка точки сразу нового статуса, время/одометр/ETA на месте, бейдж очереди «событий».
4. Включить сеть — у диспетчера тот же статус и время.

### C2. Сеть пропала на экране подтверждения (до «Верны»)
1. Открыть диалог статуса онлайн.
2. Авиарежим → подтвердить.
3. Ожидание: как C1, статус сохранён локально.

### C3. Сеть пропала после «Верны», до ответа сервера
1. Медленная сеть / Offline на `events:batch`.
2. Подтвердить статус.
3. Ожидание: UI уже новый статус, при ошибке сети событие остаётся в очереди, экран не откатывается.

### C4. Сеть появилась после завершения статуса
1. Сменить 2–3 статуса офлайн подряд.
2. Включить сеть, не трогая экран.
3. Ожидание: все события уходят по порядку, без пропуска середины.

### C5. Офлайн на статусе «документы» (фото)
1. Дойти до этапа фото. Авиарежим.
2. Снять 1–3 фото, отправить.
3. Ожидание: точка в статусе документов, фото в очереди («фото N»), превью/карточка не пустые.
4. Включить сеть — фото на сервере, статус документов применён.
5. Негатив: 0 фото — дальше нельзя.

### C6. Сеть пропала во время загрузки фото
1. Начать загрузку на слабой сети, выключить интернет на середине.
2. Ожидание: фото остаются на телефоне, статус не теряется, повторно не нужно снимать заново; после сети уходят.

### C7. Отмена сохранения фото
1. Начать выбор/сохранение и отменить, если есть отмена.
2. Ожидание: статус не прыгает в «документы» без фото.

### C8. ETA при выезде офлайн
1. «Выехал на точку» офлайн, ETA пустое — кнопка «Верны» недоступна.
2. Заполнить ETA, подтвердить.
3. После сети ETA видно диспетчеру / на карточке точки.

### C9. Ручное время и одометр офлайн
1. Поменять время вручную, ввести одометр, офлайн подтвердить.
2. После сети значения совпадают, источник времени «ручной».

### C10. Последняя точка рейса офлайн
1. Закрыть последнюю точку (фото) без сети.
2. Ожидание: рейс не «исчезает в никуда» до синхронизации; после сети рейс в истории, активный пуст.
3. Негатив: открыть детали из истории офлайн — есть снимок, если рейс открывали раньше.

### C11. Параллельно статус + принятие (не должно быть)
1. Один активный рейс. Второй назначенный принять офлайн, не закрывая первый.
2. Ожидание: поведение как в онлайне (не два активных); очередь не путает route_id.

## D. Откат статуса

### D1. Откат ещё не ушедшего статуса
1. Офлайн сменить статус.
2. Сразу «откатить».
3. Ожидание: карточка вернулась, очередь событий уменьшилась, на сервер ничего не уйдёт.
4. Включить сеть — у диспетчера старый статус.

### D2. Откат уже синхронизированного статуса без сети
1. Сменить статус онлайн, дождаться пустой очереди.
2. Авиарежим → откатить.
3. Ожидание: на телефоне предыдущий статус, в очереди «прочее», после сети диспетчер видит откат.

### D3. Сеть пропала в момент отката
1. Нажать откат на медленной сети / Offline на revert.
2. Ожидание: локально уже откат, затем досылка.

### D4. Двойной откат
1. Откатить офлайн дважды подряд.
2. Ожидание: второй раз «откатывать нечего» или корректный второй шаг назад, без порчи точки.

### D5. Откат + новое продвижение до сети
1. Офлайн: статус вперёд → откат → снова вперёд.
2. После сети итоговый статус один, без «прыжка» лишнего этапа на сервере.

## E. Отказ сервера (единый источник правды)

Нужен стенд, где переход заведомо нельзя (чужой рейс, неверный переход, отозванный рейс).

### E1. Сервер отклонил статус
1. Локально статус уже сменился, сеть есть, batch вернул invalid/forbidden.
2. Ожидание: экран **откатывается** к предыдущему статусу, сообщение об ошибке, событие не висит вечно в очереди.

### E2. Сеть появилась, и пачка частично принята
1. Офлайн три статуса, на сервере второй недопустим.
2. Ожидание: допустимые применены, недопустимый откатил UI, очередь не зациклена.

### E3. Дубликат события
1. Повторная отправка того же `client_event_id` (убить приложение на середине синка).
2. Ожидание: duplicate считается успехом, очередь очищается, статус не откатывается.

## F. Чаты

Проверять три типа: чат рейса, общий чат/комната, чат расчёта ЗП.

### F1. Открыть чат офлайн после кэша
1. Онлайн открыть чат, пролистать историю.
2. Авиарежим, выйти и зайти в тот же чат.
3. Ожидание: история на месте.

### F2. Открыть чат, который никогда не открывали
1. Авиарежим, открыть другой чат из хаба.
2. Ожидание: «история недоступна без сети», приложение не падает.

### F3. Текст офлайн
1. Отправить 2–3 сообщения без сети.
2. Ожидание: пузыри сразу видны, метка **«ожидает»** (не галочки), очередь «прочее».
3. Включить сеть — «ожидает» сменяется галочками, у собеседника сообщения в порядке.

### F4. Сеть пропала в момент отправки текста
1. Нажать отправить и сразу Offline.
2. Ожидание: сообщение не пропадает, остаётся «ожидает», потом уходит.

### F5. Сеть появилась, пока открыт чат
1. Как F3, не выходя из чата включить сеть.
2. Ожидание: pending заменяются серверными, без дублей одного текста.

### F6. Сеть появилась после закрытия чата
1. Отправить офлайн, выйти в хаб, включить сеть.
2. Зайти снова — сообщения доставлены, не только локальные.

### F7. Файлы офлайн
1. Вложить фото/файл без сети.
2. Ожидание: явная ошибка «файлы только при сети»; если был текст — текст в очереди.
3. Негатив: повтор вложения онлайн — файл уходит.

### F8. Хаб чатов офлайн
1. Открыть «Чаты» онлайн.
2. Авиарежим, перезайти в хаб.
3. Ожидание: список комнат/диалогов из кэша.
4. Негатив: создать комнату / рассылку (админ) офлайн — ошибка, без порчи хаба.

### F9. Несколько чатов в очереди
1. Написать в чат рейса, комнату и ЗП офлайн.
2. После сети все три доставки, очередь пустая.

## G. Геопозиция

### G1. Гео офлайн при включённой шаринге
1. Разрешить гео онлайн.
2. Авиарежим, открыть рейс / дождаться автоотправки.
3. Ожидание: точка на телефоне обновляется, в очереди «прочее», после сети координаты у логиста.

### G2. Запрос гео от логиста, пока водитель офлайн
1. Логист запрашивает гео.
2. Водитель без сети, затем сеть.
3. Ожидание: после появления сети координаты уходят (из очереди или новым запросом), приложение не зависает.

### G3. Отказ в доступе к GPS
1. Запретить геолокацию.
2. Ожидание: понятное сообщение, очередь не растёт бесконечно.

---

## H. Зарплата и прочие экраны водителя

### H1. Список расчётов офлайн
1. Открыть зарплату онлайн.
2. Авиарежим → снова зарплата.
3. Ожидание: последний список на месте.
4. Негатив: другой период, который не открывали — пусто/пояснение.

### H2. Подтвердить расчёт офлайн
1. Открыть расчёт → подтвердить без сети.
2. Ожидание: статус «подтверждено» сразу, очередь, после сети у бухгалтера подтверждено.

### H3. Комментарий к расчёту офлайн
1. Оставить комментарий без сети.
2. Ожидание: локально «с комментарием», после сети комментарий на сервере.

### H4. CSV / новые данные
1. Выгрузка CSV офлайн — ошибка, список не стирается.

### H5. Уведомления офлайн
1. Список, открытый онлайн, остаётся.
2. Отметить прочитанным офлайн — галка локально, после сети на сервере.
3. Пуш без сети не обязателен; после сети счётчик сходится.

### H6. Контакты логиста на рейсе
1. Открыть детали рейса онлайн (контакты видны).
2. Офлайн открыть снова — телефоны на месте, звонок с телефона работает.

## I. Очередь, порядок, стабильность

### I1. Смешанная очередь
За один офлайн-сеанс: принять (если актуально) + 2 статуса + фото + откат одного + текст в чат + гео + подтверждение ЗП.  
Включить сеть.  
Ожидание: принятие и статусы/фото в правильном порядке; чат/гео/ЗП тоже уходят; бейдж очереди → 0; нет «вечной Синхр.».

### I2. Слабая сеть (2G / троттлинг)
1. Chrome: Slow 3G / Offline чередовать.
2. Не двойные статусы, не дубли чата, UI не зависает > 75 с (сторожок сброса синка).

### I3. Сервер недоступен, интернет есть
1. Wi‑Fi без доступа к API (или стоп сервера).
2. Ожидание: «Нет сервера», локальные действия как офлайн, после поднятия API — синк.

### I4. Фоновая вкладка
1. Набрать очередь, свернуть / другой браузер на 5+ минут, вернуть с сетью.
2. Ожидание: синк возобновляется.

### I5. Два окна / два телефона одного водителя
1. Офлайн статусы на A, онлайн работа на B.
2. После сети A: конфликт invalid → откат UI на A к серверу. Не два разных «истинных» статуса.

### I6. Переподключить
1. С очередью нажать «Переподключить».
2. Ожидание: очередь не стирается; если есть обновление PWA — перезагрузка; затем синк.

## J. Чего офлайн быть не должно (негатив границ)

| Действие | Ожидание |
| --- | --- |
| Вход / смена пароля | Только с сетью |
| Назначение рейса логистом | Не водительский офлайн |
| Файлы в чате | Только с сетью, текст можно в очередь |
| Скачать вложение чата, которого нет в кэше | Ошибка, чат живой |
| CSV зарплаты | Ошибка |
| Админ: создать рейс, списки ТС | Ошибка, без порчи кэша водителя |

## Краткий прогон «за 15 минут»

1. Онлайн: открыть рейс, чат, ЗП, уведомления.
2. Авиарежим.
3. Принять или сменить статус + ETA; фото если этап документов.
4. Написать в чат рейса; попытаться вложить файл.
5. Откатить последний статус и снова продвинуть.
6. Подтвердить расчёт, если есть.
7. Убить приложение, открыть снова — данные на месте, «ожидает» в чате.
8. Включить сеть — очередь 0, диспетчер/бухгалтер видят то же.
9. Повторить «пропала сеть в момент кнопки» на принятии и на статусе.
10. Смоделировать отказ сервера — экран откатился.
